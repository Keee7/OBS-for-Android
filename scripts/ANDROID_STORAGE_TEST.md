# Android 共享目录录像回归

适用版本：0.1.2-storage-test，versionCode 3。APK 路径、校验值见 DEVICE_TEST_QUICKSTART.md。

## 修复范围

原来的空间检查直接对录像路径调用 statvfs。Android 文档目录 content URI 不能当作 POSIX 路径，查询失败被转换为零，于是误报“没有足够磁盘空间”。共享存储的写入权限也不能通过增加旧 WRITE_EXTERNAL_STORAGE 权限解决。

公共 Download、Movies、DCIM 及其子目录使用 MediaStore 创建文件；系统目录选择器返回的 SAF tree URI 使用 DocumentsContract 创建文件。原生缓冲写入器通过一次 JNI 调用取得可定位的文件描述符，直接写入目标文件，停止时原地完成 MP4 封装。不需要临时录完整文件后复制，也没有逐帧 JNI I/O。未增加所有文件访问权限。

主存储容量通过 StatFs 检查，仍保留低于 50 MiB 时停止录像的保护。提供者无法报告容量时显示“—”，不会以零容量误停录像；创建、打开和写入仍可真实失败。仅支持可 seek 的本地文档，云端管道式提供者不支持。

共享目录使用混合 MP4 / 混合 MOV；自动 remux 对文档文件跳过。分割录像、回放缓存、FFmpeg 自定义输出暂不支持直接写入共享文档目录，启动前明确提示。文件名格式暂不支持含子目录；重名由提供者处理，保留现有文件，不执行覆盖。

## 在目标设备执行

1. 覆盖安装新版，确认版本号，无需卸载现有配置。
2. 设置 → 输出 → 录像，选择混合 MP4，关闭文件分割。
3. 录像路径输入 `/storage/emulated/0/Download/obs`（也支持 `Download/obs`）。第一次不需要先创建 obs 文件夹。
4. 录制 60 秒，正常停止，用文件管理器打开 Download/obs，确认文件非空、能播放、视频及音频完整。
5. 连续快速启动/停止两次，确认同名时生成不同文件、不覆盖旧录像。
6. 完全关闭应用后重启，再录制一次，确认目录配置保留且无需重新获取普通 Download 路径权限。
7. 改用“浏览”选择 Download/obs 子目录并授权，重复录制及重启测试。Android 不能通过 SAF 授权 Download 根目录，应选择其子文件夹。
8. 可选：对 Movies/obs、SD 卡/USB 盘已授权的本地目录重复测试；云盘和受系统限制目录不作为通过条件。

若空间确实不足 50 MiB，应继续出现容量不足提示；不要在有重要数据的设备上为测试刻意填满磁盘。

## 日志

保存 OBS 日志和 `adb logcat -d -s OBS-storage:*`。目录创建、授权或文件描述符打开失败会记录详细原因。反馈时附版本号、所填路径（或系统目录选择方式）、发生时间和可用空间，移除私人信息。

## 验证边界

桌面侧检查包括完整 Android 原生/Qt/Java/Dex/APK 构建、签名、对齐以及包内新增存储桥接符号和 Java 类。本地没有连接 Android 设备；以上写入、文件播放和重启权限流程仍需要实机回归，不能把成功构建作为这些流程已通过的证据。
