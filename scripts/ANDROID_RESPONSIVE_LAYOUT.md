# Android 响应式布局

PR #4 的小屏适配增加了按当前应用窗口尺寸切换的布局策略，不按手机/平板型号判断。

- 使用 Qt 逻辑像素。窗口宽小于 952 或高小于 552 时进入紧凑布局；恢复到至少 1000×600 后回到宽松布局。48 像素的滞回区避免临界尺寸反复切换，同时让 1024×620 等平板窗口从小窗返回后恢复宽松布局。
- 宽松布局保留至少 48 的场景/来源行高和工具按钮尺寸；紧凑布局使用至少 32 的列表行高及较小工具按钮。字体和内嵌控件需要更大尺寸时仍尊重其 size hint。
- 主窗口 resize 事件通过 120 ms 单次计时器合并。只有模式改变时才更新样式和列表布局；不添加逐帧计算或常驻轮询。
- 对话框上限取屏幕可用区与父应用窗口的交集，兼容平板分屏/小窗。上限不再人为放大到 320×240；最小内容仍无法装入时保留原有阻挡诊断。
- 宽松布局保留未选择来源时的上下文工具栏；紧凑布局隐藏空工具栏以增加预览空间。用户关闭工具栏的设置仍然生效。
- Android 禁止用户将 dock 浮动的原 PR 行为保留；非 Android 滤镜窗口继续在 showEvent 中限制高度。

独立策略检查：

```sh
c++ -std=c++17 -Wall -Wextra -Werror scripts/android-layout-test/policy.cpp -o android-layout-test
./android-layout-test
```

覆盖平板全屏、手机横屏、平板小窗、临界尺寸滞回、无效初始尺寸及 1..2048 可用尺寸的上限不越界。实际 Android 小窗坐标、触摸和软键盘交互仍需设备验证。
